# 人工决策与合成规范 v0.1

状态：ACCEPTED（用户已授权按既定路线继续 P4）  
适用范围：V1 本地自用版 P4

## 1. 目标

用户可以针对冻结简历的每个区块选择某个 Provider 建议、明确拒绝建议、直接手动编辑，并随时撤销最近一步。系统根据完整的追加式决策历史稳定重算最终简历，且每个最终区块都能追溯来源。

## 2. 决策规则

- 决策日志只追加，不覆盖或删除历史事件。
- `SELECT`：选择一个候选 Change；同一区块的新选择替代旧选择，但旧事件仍保留，供撤销恢复。
- `REJECT`：明确拒绝一个候选 Change；若它当前生效，则恢复该区块之前的有效状态。
- `EDIT`：直接替换一个现有简历区块。手动文字必须非空、最多 20,000 字，并要求 `factConfirmed: true`，避免静默加入未经用户确认的新事实。
- `UNDO`：只撤销最近一个尚未撤销的普通决策；撤销本身也追加到日志，因此可以完整重放。
- 所有事件使用连续序号、唯一事件 ID、时间和操作者来源；乱序、重复 ID 或跨基线事件必须拒绝。

## 3. 候选完整性与冲突

合成前重新验证每个被选候选：

- ChangeSet 必须通过 P1 Schema、事实语义门禁与 P3 基线匹配门禁。
- `sourceBlockRef` 的 block ID、结构路径、内容哈希和 `originalText` 必须对应冻结基线。
- P4 v0.1 完整支持 `REPLACE`、`DELETE`、`KEEP`；`INSERT` 仅支持平面区块的 `BEFORE` / `AFTER`。
- 现有 ChangeSet v0.1 没有为 `MOVE` 定义明确的前后位置，P4 不猜测其含义，发现时作为阻断冲突返回。
- 同一锚点同一位置出现多个生效 `INSERT`，或插入依赖一个已删除锚点时，必须阻止合成，等待用户处理。

## 4. 合成结果与追溯

合成结果包含稳定 `finalResumeId`、冻结 `baselineId`、决策日志 ID 和最终区块。每个区块记录以下来源之一：

- `BASELINE`：未修改的冻结简历原文。
- `PROVIDER`：采用的 ChangeSet、Change 和决策事件。
- `USER_EDIT`：用户编辑事件，以及可选的来源候选。

相同冻结基线与相同有效决策状态必须生成相同 `finalResumeId`；选择后撤销必须恢复之前的文本与 ID。

## 5. 本地存储

```text
decisions/<decisionLogId>/decision-log.json
compositions/<compositionId>/composed-resume.json
```

写入采用原子替换；已有 ID 默认禁止覆盖。所有内容只保存在当前冻结运行目录。

## 6. P4 边界

本阶段不实现 UI、DOCX/PDF 渲染、一页检查、面试内容或第三方 Skill 安装。手动事实确认只证明用户明确确认，不代表系统能够自动判断陈述真实性；最终事实责任仍由用户掌握。

## 7. 验收标准

1. 选择 A 后选择 B，B 生效；撤销后恢复 A。
2. 拒绝当前方案后恢复冻结原文或之前的有效方案。
3. 未确认事实的手动编辑被阻止；确认后的编辑具有 `USER_EDIT` 追溯。
4. 候选区块哈希错误、未知候选、冲突插入和 MOVE 均阻止合成。
5. 相同有效状态稳定重算；每个最终区块均有完整来源。
6. 决策日志和合成结果可从本地重新读取。
